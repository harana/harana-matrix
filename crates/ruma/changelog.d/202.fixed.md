A `.well-known/matrix/client` file that lists a value under both its stable and
its unstable name (`m.rtc_foci` and `org.matrix.msc4143.rtc_foci`, say) no
longer fails to deserialize. `#[serde(alias)]` maps both names onto one field
and then rejects the second as a duplicate field, which failed the whole
document and left the client with no discovery information; the two names are
now read as separate fields and reconciled, preferring the stable one.

`#[response(manual_body_serde)]` now reaches `#[derive(Response)]`, which it
did not before: the attribute was parsed and dropped, so a response asking for
manual body serde still got the derived impls and failed to compile.
