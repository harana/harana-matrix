The level required to trigger an `@room` notification, taken from the
`notifications` section of the `m.room.power_levels` event, is now exposed as
`RoomPowerLevelChanges::notification_room`, and can be changed like any other
power level.

`Pusher` gained `set_disable_badge_count`, which sets the
[MSC4076](https://github.com/matrix-org/matrix-spec-proposals/pull/4076)
`disable_badge_count` flag on an HTTP pusher's data. A client that computes its
own badge counts can set it so the homeserver stops sending high-priority
pushes whose only purpose is to update the unread count.

`Room::default_notification_mode` returns the notification mode a room falls
back to when the user hasn't defined one for it, i.e. the account-level default
for rooms of that kind. Unlike `Room::notification_mode` it never requests the
room's encryption state over the network, so it is safe to call on a hot path.

`SlidingSyncBuilder::mark_tracked_users_dirty_without_pos` controls whether a
sliding sync instance invalidates the device list cache when it sends a request
without a `pos`. A short-lived instance that shares its crypto store with a
long-lived one — the notification process on iOS, for instance — should disable
it: it starts without a `pos` on every run, and invalidating the whole cache
each time forces a `/keys/query` for every tracked user.
