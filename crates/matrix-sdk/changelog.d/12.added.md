`MatrixSession` carries the URL of the homeserver it was created against.
`MatrixAuth::session` fills it in, and `MatrixAuth::restore_session` points the
client at it, so restoring a stored session no longer needs a `.well-known`
lookup to find the server the tokens belong to. It is optional, so a session
saved before this field still restores.

A homeserver can move: a server name that delegated to one host can come to
delegate to another. A client that resolved its homeserver from a server name
now notices that as it revalidates the well-known file, and follows the move.
A client that was handed a homeserver URL, which is how a deployment points its
clients at a proxy, stays where it was put; the difference is logged either
way.
