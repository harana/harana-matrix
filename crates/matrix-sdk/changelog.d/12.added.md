`MatrixSession` and the OAuth 2.0 `UserSession` carry the URL of the homeserver
they belong to. `MatrixAuth::session()` and `OAuth::user_session()` fill it in,
and restoring a session that has one points the client at it, so restoring no
longer needs the `.well-known` lookup that discovering the homeserver costs at
every start and that fails when the device is offline. The field is optional, so
a session stored before this still deserializes and leaves the client where it
was pointed.

`Client::revalidate_homeserver()` asks the `.well-known` file again and follows
the homeserver if it moved, reporting whether it did so the caller can store the
session again; any other read of that file that finds a new address follows it
too. Both respect `ClientBuilder::respect_login_well_known`, which is what keeps
a manually configured homeserver URL -- a proxy in front of the homeserver, say
-- from being replaced by what discovery advertises.
