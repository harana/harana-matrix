`clippy::future_not_send` is now denied crate-wide on non-WASM targets, rather
than in the two places it was applied by hand, so an async method that returns
a future the caller cannot spawn is caught at build time.

Getting there needed bounds on generic parameters that were missing them, which
tightens a few public signatures: `Room::send_state_event` and
`send_state_event_for_key` need `Send` content and a `Sync` state key,
`Media`'s file and thumbnail methods need `Sync` event content,
`Room::event_push_actions` and `PushContext::for_event` need a `Sync` event
type, and `Client::sync_with_callback` needs a `Send + Sync` callback returning
a `Send` future. All of these already held for the types callers pass.
