The access token is refreshed before it expires rather than only after a request
has been rejected with `M_UNKNOWN_TOKEN`. The lifetime the homeserver reports at
login, at registration and at every refresh -- and the one the OAuth 2.0 token
endpoint reports -- is now tracked, and a request made within a minute of the
expiration refreshes first, so it goes out with a token that is still valid.
The reactive refresh stays as the fallback, for a restored session whose token
lifetime is unknown and for a homeserver that expires a token early.
