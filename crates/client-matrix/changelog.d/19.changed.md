Running several syncs concurrently on the same `Client` is now refused instead of
silently interleaving. `Client::sync_once()` returns `Error::ConcurrentSync`, and
`Client::sync_stream()` yields it once and then ends, when a sync loop
(`Client::sync()`, `Client::sync_with_callback()`, `Client::sync_stream()`) or
another `Client::sync_once()` call is already running for that client. Mixing
them could drop syncs and let an older response overwrite newer state.
