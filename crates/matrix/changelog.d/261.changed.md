`Backups::wait_for_steady_state()` no longer starts an upload: it only observes
one, matching what its name says. Use the new `Backups::trigger_upload()` to ask
for the room keys that aren't backed up yet to be uploaded, then await the
future to wait for it.

The future also no longer returns on the first `UploadState::Done`. That state
means the upload task finished the batch it was working on, which doesn't
include the keys queued while waiting, so callers could be told the keys were
backed up when they weren't. It now returns only once no room key is left to
upload. It subscribes to the upload state when it is created rather than when it
is awaited, so an upload triggered in between can't complete unnoticed.

`WaitForSteadyState::with_delay()` applies the delay immediately rather than
when the future is first polled, and puts back the value the client started
with once the wait resolves.
