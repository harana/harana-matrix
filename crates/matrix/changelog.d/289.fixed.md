Setting an encrypted room to "mentions and keywords only" no longer stops
notifications for that room entirely. The room-level `dont_notify` rule kept the
homeserver from pushing anything at all: it cannot read the ciphertext, so it can
never tell that a message mentions the user, and the device never woke up to find
out. Such a room now also gets an `Override` rule that keeps its encrypted events
notifying; the client evaluates the push rules again on the decrypted event, where
the room-level rule does apply, so non-mentions are still filtered out —
client-side, where the mention is actually visible.

An edit that triggers a notification no longer increments the unread notification
count a second time for what the user sees as a single message: its notification
is folded into the count of the event it replaces. An edit that mentions the user
is the exception and still counts, since per the spec an edit's `m.mentions` only
carries users that weren't mentioned in the original event.

A thread is now automatically subscribed to when an in-thread event *mentions* the
user, rather than whenever one merely triggers a notification. In a room set to
notify on all messages, the latter subscribed the user to every single thread of
the room. An explicit unsubscription is also sticky now: once the user has
unsubscribed from a thread, only a manual subscription can subscribe them again,
so the next message in that thread no longer undoes their choice.
