`MessagesOptions` now excludes live location updates (MSC3489 beacon events) from `/messages` responses by default, which speeds up pagination in rooms where somebody is sharing their location: such a room accumulates a beacon event every few seconds, while a client only needs the `beacon_info` state event and the most recent updates, which both come from sync. Use `MessagesOptions::include_live_location_updates()` to get them back. Note that in an encrypted room the server can't tell a beacon from any other event, so they are returned either way.
