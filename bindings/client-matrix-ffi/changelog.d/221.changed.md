`RoomInfoListener::call` now takes the reasons for the update alongside the
`RoomInfo`, as a `Vec<RoomInfoUpdateReason>`. The listener delivered a whole
`RoomInfo` on any change without saying what changed, so clients had to diff the
fields by hand to avoid needless re-rendering. The initial value delivered on
subscription carries no reasons; an update whose cause the SDK doesn't classify
carries `Unknown`. `Room::subscribeToRoomInfoUpdates` now reads the same
notable-update stream `Client::subscribeToRoomInfo` already used.
