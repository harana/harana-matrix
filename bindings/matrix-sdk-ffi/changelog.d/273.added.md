Add `Encryption::bootstrap_cross_signing`, so a client that authenticates first
and offers a security setup step afterwards can create a cross-signing identity
explicitly rather than relying on `auto_enable_cross_signing` at client build
time. It reports a typed `CrossSigningBootstrapOutcome` (`Bootstrapped`,
`AlreadyBootstrapped`, `AuthenticationRequired` with the UIAA challenge, or
`Unavailable`), never returns private key material, and leaves an existing
identity untouched.
